## 激光与赔付

网格按行优先，5×4 编码前缀为 `-,`，字符减 40 得到符号；眼球 ID 13、FS 为 12、Wild 为 0。

`laser.data` 包含 `origin`、方向 `d`、依次命中的位置数组 `p`、每步命中后的累计倍率数组 `m`。`totalMulti.data.m` 为结算时 20 格数值。原版例子：

| 原点／方向 | 原回包路径 | 证据 |
| --- | --- | --- |
| 17／UpLeft | 11, 5, 1, 7, 13, 19 | 278：左边与顶部反射 |
| 18／UpLeft | 12, 6, 0 | 325：左上角出口 |
| 19／Up | 14, 9, 4 | 397：右上角出口 |
| 18／Up | 13, 8, 3, 3, 8, 13, 18 | 407 免费内：顶部垂直反射重复报告格 3 |

激光后再算线奖。`gridwin.data` 的 `mask`、`symbol`、`count` 与 `winAmount` 逐笔对照；有倍率时还保存 `baseWinAmount` 和 `winMultipliers`，普通 1 倍不加入后者。

`main.js` 的 `addLaserHandler` 枚举 13 对起止位置动画：最左眼球只向上／右上，最右只向上／左上，三个中间眼球各有三条有效路径。本地双发从有效方向中取两个，避免在边缘重复选择同一条物理路径。

使用线上第一个自然符号，连续到首次不匹配。五个全 Wild 使用 Wild 赔付表；不使用盘面上不存在的其他符号为 Wild 前缀另选高奖。每线只派一笔最高合法奖金。

## 本地生成选择及未验证边界

本地使用原表中普通／免费符号集合独立选择，再根据单独概率插入眼球或 FS。这不等于还原原服务器转轴抽样。倍率可选值按帮助保留，权重为本地配置。13 条有效激光路径、逐次倍率变化和算奖均由原版样本回归通过。本地另外穷举五眼球双发的 864 种方向顺序，数值和最终网格一致；未把未出现的极端组合或倍率随机分布写作原服务器已确认规则。

用户已要求直接按公开规则完成实现；以下仅为后续原版证据核对项，不是未实现功能或交付阻塞：

1. 已有 Zigzag 50 回合、2–4 个眼球及交叉路径；继续补五眼球、尚未覆盖的激活顺序与多重重复命中。
2. 两档购买及结算确认已补齐；NO-BRAINER 已有追加两次，后续可补三 FS 追加四次及其他未覆盖的双发组合。
3. 自然五 FS 隐藏回合与 10000 倍封顶回包（含免费内提前结束），不能把本地验收样本标为原版证据。
4. 原版待领奖时刷新，比较 authenticate 的 `events`、`pendingWin`、继续请求及唯一派奖。
5. 如通用 CSS 旧默认 `hunt_frame.png` 实际请求失败，补抓具体布局和资源覆盖配置。当前宣告资源 441 项均已获取，已测原版页面没有依赖该旧默认名。

## 匿名校时协议修正

原版请求 679–690 中的 `keepAlive` 校时请求使用全零 UUID，响应 `statusCode=0`、`accountBalance=null` 和 UTC `serverTime`。原客户端 `casino/hacksaw-casino.min.js` 的 `timeCheck` 也明确发送此 UUID。原本地处理把它当成钱包令牌，回复错误码导致周期性未处理 Promise 警告；现按该已抓取协议处理。实际非零会话仍经过钱包鉴权，匿名校时不创建账号或返回余额。
