# 游戏开放与目录展示

2026-11-06 最新约定：用户明确要求运营可以开放任何游戏，不设置收集完整性的限制。本规则取代此前“特殊玩法原版证据未齐禁止接入”的硬性拦截。

## 开放与接入

- 运营控制台显示全部 19 款游戏、开放状态、收集情况及缺失项。平台管理员及运营人员可开放或关闭任何游戏，不需要收集审核或额外的强制开放确认；商户和平台只读角色不能修改。
- 开放开关持久化到控制库 game_availability，无记录默认关闭；更新校验版本并写入审计。网关与后台共用同一库，修改后无需重启即生效。本次规则修改不会自动开放游戏。
- 商户工作台、签名 games/list 和商户导出只显示已授权、已开放且钱包兼容的游戏，不返回内部缺失项或来源。公共网关目录只展示已开放游戏。收集情况不再限制开放、新启动或新整局。
- 关闭游戏时，新启动和新增付费整局返回 HTTP 403 / GAME_CLOSED。已受理的幂等操作、待确认扣款/派彩及已开始免费/奖励回合继续恢复、续局和结算，结束后不能开始下一整局。
- 新商户默认授权全部游戏；创建 API 省略 games 同样默认全授权，钱包金额单位统一固定为 10000，商户无需传入或回传精度字段。显式部分授权、空授权和已有商户限制保持不变。授权不等于开放；后续新增游戏不会隐式扩大旧商户授权。
- 两位及四位美洲野牛与其余游戏共用开放检查，RTP/预派彩模式均适用。原独立开发入口、大厅和游戏内原版功能保留。

## 收集记录

[game-readiness.json](../server/config/game-readiness.json) 保留逐款待补项、来源、维护表校验和与核对日期，依据维护表及 [各游戏待验证与资源缺口](game-validation-and-resource-gaps.md)。当前 19 款均有尚未关闭的特殊玩法证据或验证记录；开放游戏不会清空这些缺失项，也不代表已经验证完成。本次没有重新全量抓取或核验原站状态。

补抓仍须先检查最新已保存请求、响应、解码结果和资源，再补缺失分支，并保存从触发到恢复可下注的完整样本及重试、恢复、唯一结算证据。更新清单时同步对应 Markdown；只有对照证据完整且实现已验证，才能标记 collection_complete、清空 blockers 并登记 evidence。本地实现或模拟测试不能冒充原版证据。这些记录供运营查看，不作为商户接入限制。

RTP 标定和特殊玩法收集分别展示，不能相互替代。

## 目录导出

两端使用单个“导出目录”按钮，在弹窗选择阅读版 HTML、表格版 CSV 或数据版 JSON。三种格式都只包含游戏品牌、中文名、英文名、接入 ID。HTML 使用适配 A4 打印的四列表格，CSV 带 UTF-8 BOM 与公式防护；JSON 的 games 数组每项只有 brand、title_zh、title_en、id，id 对应启动接口的 game_id。运营导出全部游戏，商户只导出当前可接入游戏，不附加开放状态、RTP、收集情况、来源或商户信息。

导出保留登录鉴权、games.read 权限、CSRF 和租户隔离，商户不能指定其他商户扩大范围。HTML 转义有效，不包含密钥、原始抓取令牌或玩家资料。目录与启动检查使用同一开放配置。

中英文展示名按固定游戏代码维护于 `server/gateway/game-names.ts`，不改变接入 ID。美洲野牛、福兔、麻将胡了 2、吸血鬼、超级王牌、大鲈鱼、奥林匹斯之门沿用现有维护表或大厅中文标签；其余中文名为本平台展示译名，不宣称已核对厂商官方译名。英文名沿用现有游戏目录，保留 DELUXE、POP、WinX 等版本标记。
