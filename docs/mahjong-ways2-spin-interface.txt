麻将胡了 2：Spin 接口规则分析
日期：2026-10-13

结论与证据范围
本文件描述接口协议和确定性结算规则，不是回放方案，也不是原版随机出牌算法。
使用原客户端解码了 533 条抓取响应：530 条有效、3 条短响应未解码。
覆盖 282 个完整付费回合，另有 1 个未结束的付费/免费游戏回合。
免费游戏进入 3 次、完整结束 2 次；未结束过程包含一次追加 10 次的事件。
所有有效请求均为 btt=2、pf=1、wk=0_C、cs=0.3、ml=2。
因此跨下注档位、其他钱包、货币小数位、购买功能和失败请求处理尚未获得实测覆盖。

复核方式
从仓库根目录执行：
python -m tools.pg_capture.mahjong_ways2.analyze_spin diagnostics/spin-decoded-all.json --output "clients/mahjong-ways2/fixtures/spin-rule-evidence.json"
35 类核对没有失败。验证对象包括：530 张独立算奖牌面、289 个中奖符号组合、213 次连消补牌、84 对免费状态变化。
analyze_spin.py 的 evaluate_board 只使用牌面、下注和倍率计算中奖，不读取响应给出的 wp/lw/snww/rwsp。
原始请求、会话参数及完整解码记录保留在忽略的 diagnostics 中；公共证据文件不包含凭据。
fixtures/spin-protobuf-schema.json：从原客户端导出的交易和钱包 Protobuf 模型。
fixtures/spin-rule-source.json：赔付表、有效位置、原版 GameInfo 阈值、客户端 SHA256。
fixtures/spin-rule-evidence.json：逐类验证数量、失败样本行号、赔付表覆盖及免费事件。

一、传输和请求
POST /game-api/mahjong-ways2/v4/Spin，Content-Type: application/octet-stream。
请求和响应均为二进制 Protobuf，经 Fisher–Yates 字节置换并插入一个字节。
游戏编号 74 的数字和为 11。请求种子位于 request[11 % (request.length-1)]。
响应解码必须使用配对请求的种子；去除插入位后逆向执行交换。
随机序列使用客户端的非截断 BigInt xorshift，不能替换成 32 位或 uint64 溢出运算。
实现参考 server/adapters/pg/protocol.py；这是传输混淆种子，不能用于推算服务器牌面。
解码后的成功 Spin 为一个平铺 protobuf；交易模型、钱包模型分别解释同一份字节。
不存在必须包成 JSON dt.si 的步骤。客户端将缺省标量补零，将若干缺省容器规范化为 null。

请求字段（protobuf 字段号 / 类型）
atk 1/string：公共请求会话参数；不参与本报告的算奖公式。
btt 2/int32：下注类型参数；本批全部为 2，不把本地 mock 的 1 当成原版依据。
pf 3/uint32：平台参数，本批为 1。
id 5/string：前一次响应的 sid；初始或重新进入时见到 "0"。
wk 12/string：钱包键，本批为 0_C。
cs 21/double：单份下注基数。
ml 22/int32：下注倍数，与连消倍率 wm 是不同概念。
fb 24/int32、ab 31/int32：schema 中存在，当前有效样本未覆盖其功能。
MJAPIClient.spin 显式发送 pf/wk/cs/ml/id，公共层补充公共字段。
529 对相邻成功响应中 527 次发送前一个 sid，2 次重新以 id="0" 开始。
这证明客户端的衔接方式，不能据此证明服务器的重试幂等策略、sid 生成规律或失效 id 处理。

二、状态机和请求连续性
GameConstant.TransitionState 明确命名：
1=NORMAL，4=RESPIN，21=FREE_SPIN，22=FREE_SPIN_RESPIN。
st 表示本次请求执行的状态，nst 表示执行完毕后下一次请求应进入的状态。
样本中相邻响应的 next.st == previous.nst，529/529 一致。
sid 每步标识，psid 归属一个付费起始回合，跨普通连消和该回合的免费游戏保持关联。
付费起始响应 sid == psid。

样本验证的转移优先级：
1. 本次 tw > 0：普通状态转 4，免费状态转 22，继续连消。
2. 普通状态无奖：sc >= 3 则转 21，否则转 1。
3. 免费状态无奖：结算追加次数后 fs.s > 0 则转 21，否则转 1。
因此同一画面同时有中奖和足够散布符时，要先完成中奖连消；不能提前重置牌面。
进入 21 的下一次请求才扣一个免费次数；进入 22 的请求不扣次数。
一个用户可见的旋转可能对应多次 Spin HTTP 请求。

三、牌面、符号和赔付
orl：当前算奖前的原始牌面；rl：中奖金牌转百搭后的牌面。
35 个位置按 5 列 × 每列 7 格排列，索引从 0 开始，列号=floor(index/7)。
有效算奖位置：
第 1 列 [1,2,3,4]；第 2 列 [8,9,10,11,12]；第 3 列 [15,16,17,18,19]；
第 4 列 [22,23,24,25,26]；第 5 列 [29,30,31,32]。
其他位置属于缓冲/隐藏格，仍参与连消时完整 7 格列数据的移动，不能直接删去。
sc 等于有效位置中的符号 1 数量，530/530 一致。

符号 ID / 客户端名称 / 连中 3、4、5 列时的每路基础赔付
0  百搭 WILD：替代普通符号，不是独立赔付符号。
1  散布 SCATTER：用于免费游戏，不按普通连列公式赔付。
2  发 GREEN          10 / 25 / 50
3  中 RED             8 / 20 / 40
4  白 WHITE           6 / 15 / 30
5  八万 CHAR8         5 / 10 / 15
6  五筒 BALL5         3 /  5 / 12
7  五条 BAMBOO5       3 /  5 / 12
8  三筒 BALL3         2 /  4 / 10
9  二筒 BALL2         1 /  3 /  6
10 二条 BAMBOO2       1 /  3 /  6

赔付表来源是客户端 GameConstant.PayOutData，不是通过输赢频率拟合。
27 个表格单元中 26 个被真实样本中奖覆盖；白板连中 5 列的 30 倍仅有客户端代码证据。
对每个普通符号，从最左列连续查找该符号或百搭，遇到没有匹配的列即停止；至少连续 3 列才中奖。
wp[symbol] 是这些列内所有匹配位置；snww[symbol] 是各列匹配数量之积。
按最长连续列数取一档赔付，不把 3/4/5 列奖重复叠加。
rwsp 是 JSON 字符串，保存各中奖符号本次使用的基础赔付率。
lw[symbol] = cs * ml * rwsp[symbol] * snww[symbol]
tw = sum(lw.values()) * wm；本批 ctw == tw。
独立牌面计算与 530 条响应的 wp、snww、rwsp、lw、tw 全部一致。
尚未观察“左侧数列完全是百搭、无普通符号”的极端服务器牌面；不能用当前验证外推其生成可能性。

四、金牌、消除和补牌
ssb：本次处理前特殊牌 ID -> 位置；ss：本次处理后仍为金牌的 ID -> 位置。
设 W=wp 全部位置的并集，G=ssb 的位置集合。
中奖金牌位置 C=W∩G：保留格子，rl[C]=0，转成百搭；这些 ID 从 ss 中移除。
真正消除的位置 ptbr=W-G。
未中奖格子与未中奖金牌保持；旧百搭参与中奖时正常消除。
以上规则在 530 条响应全通过；早期“rl 始终等于 orl”“ptbr 等于全部 wp”的结论不适用于金牌样本。

rs 是本次连消如何从上一响应牌面生成当前牌面的说明：
rns：5 个补牌数组，顺序对应 5 列；每列从上一 rl 中删除上一 ptbr，再将本次 rns 前置。
公式：current.orl[column] = current.rs.rns[column] + surviving(previous.rl[column])。
213 次连消可重建完整 35 格牌面，全部一致；算法不需要读取当前 orl 来决定补牌结果。
rnss：各列 rns 中新增金牌的局部索引，换成绝对位置为 column*7 + index。
旧金牌位置向后移动的距离，是同列在它后面被删除的格子数。
sspt：特殊牌 ID -> PositionTransformation，内部 Protobuf 字段 1=原位置、2=新位置。
仅移动的旧金牌出现在 sspt；新增金牌由 rnss 描述。213 次验证全部一致。
导出的通用 schema 将 sspt 值保留为 bytes，需再解码这两个 varint 字段。
bsb 在模型中命名 brokenSpecialBlock，但本批没有非空样本，不强行规定生成行为。
金牌 ID 的分配、牌面/金牌生成概率，仍需和确定性的移动规则分开。

五、倍率与计数
普通轮 wm = [1,2,3,5][mi]；免费轮 wm = [2,4,6,10][mi]。
st=1 或 21 时 mi=0；每次进入连消 mi=min(previous.mi+1,3)，达到末档后保持。
cwc：当前连续中奖次数，中奖递增、无奖归零，新普通/免费旋转重新开始。
pcwc：本批仅付费起始响应中奖时为 1，其余为 0；不要外推未捕获玩法。
fstc：本付费回合内各后续状态已执行的次数，计数键 4/21/22；每次对应请求递增。
上述规则均在 530 条样本中一致。

六、免费游戏与奖金累计
fs.s=当前剩余免费次数，fs.ts=已授予的总次数，fs.nosa=本次新增次数。
捕获到两次 3 散布符初始授予 10 次，一次 4 散布符初始授予 12 次。
捕获到一次免费连消结束时 3 散布符追加 10 次：剩余 3->13，总数 12->22（抓取行 4089）。
“10 + 2*(sc-3)”与目前 3/4 散布符触发一致，但 5 个及以上和更高次数追加未被样本验证。
在同一免费过程中：
current.fs.s = previous.fs.s - (current.st==21 ? 1 : 0) + current.fs.nosa
current.fs.ts = previous.fs.ts + current.fs.nosa
current.fs.aw = previous.fs.aw + current.tw
84 对相邻免费状态均通过。

aw：整个付费父回合累计奖金，包括触发前普通连消奖金及后续免费奖金。
fs.aw：仅免费部分累计奖金，首次授予免费游戏时为 0。
ssaw：当前一次普通/免费旋转及其连消累计；每个新的 st=21 重置为本次 tw。
因此 aw、fs.aw、ssaw 并不等价。
实例：第一段完整免费游戏结束，aw=944.4、fs.aw=922.8，差额 21.6 是触发前奖金。
第三段虽然缺少退出响应，其已捕获追加次数和结算步骤仍可参与局部规则验证。

七、扣款和余额
tbb = cs * ml * 20。当前 cs=.3、ml=2，所以基础下注 12。
只有 st=1 时 tb=tbb，其余普通连消、免费旋转和免费连消 tb=0。
blb：本次扣款前余额；blab=blb-tb；bl=blab+tw。
np=tw-tb 是本次接口响应的净变化，不是整个父回合净收益。
在正常结算里，父回合净收益为最终 aw - 起始 tbb。
所有 530 条余额、扣款、派彩关系通过。
金额 wire 类型为 double；实现算奖宜用十进制金额，中途舍入规则在其他下注档位仍需核对。

八、大奖阈值与动画触发
真实 GameInfo/Get 的字段 900 内是公共游戏信息，其字段 22 内为 WinThreshold。
3 次原版 GameInfo 抓取（行 1256/1648/3406）均为：mw=3、bw=5、mgw=15、smgw=35。
阈值金额 = cs * ml * maxLineNumber * 对应倍率；maxLineNumber=20。
gwt 与本次 tw/tbb 的档位一致：<3 为 -1，>=3 为 1，>=5 为 2，>=15 为 3，>=35 为 4。
530 条一致，但最高档上界和封顶截断没有样本覆盖。
客户端 MJPrizeState.playPrize/Er 在 nst 为 NORMAL 或 FREE_SPIN 且 ssaw>0 时，
用 ssaw 与 bigWinThreshold 比较并触发大奖控制器；控制器继续使用 mega/superMega 阈值。
因此动画按一次旋转连消累计奖判断，不能简单把 gwt 当成“现在立刻播放大奖”的开关，
也不能用整段免费游戏累计 aw 代替每次旋转的 ssaw。

发现的本地配置差异：fixtures/game-info.json 仍为 mw=5、bw=20、mgw=35、smgw=50。
这是旧本地 fixture，不代表本次采集环境；本轮分析未改动运行中的回放服务或钱包。
不同运营环境是否使用不同阈值尚未调查，真正接口实现应从 GameInfo 配置取值。

九、尚未确定，不能假装已还原
服务器随机数算法、转轴条带、符号权重、金牌出现概率、RTP 和稀有事件频率。
大奖/免费触发概率不能用这批小样本证明；传输种子不能当成牌面随机种子。
余额不足、断网重试、重复 id、并发请求、认证过期、3 条短错误响应的正式错误协议。
fb/ab 功能、特殊钱包、货币精度、最高赢额封顶、5+ 散布符、未出现的特殊块事件。
hashr 的完整规范和校验用途，ge/pmt/ocr/mr 等辅助字段对不同客户端流程的强制要求。
重新生成 sid、金牌 ID 和未知辅助字段时的服务端约束。

后续实现边界
可基于已验证规则建立确定性“牌面 -> 中奖 -> 金牌转换 -> 消除 -> 补牌 -> 状态/余额”引擎。
牌面生成器必须作为单独策略：允许自定义本地概率，但应明确与原版概率不同或尚未验证。
当前 analyze_spin.py 已完成独立算奖和规则校验，没有把现有本地 Spin 服务替换成新引擎。
