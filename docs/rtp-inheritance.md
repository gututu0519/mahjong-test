# RTP 继承与逐款标定

2026-11-05。商户未指定目标时默认 96%（9600 bp）。当前实现保留玩家单独配置，依次选择：当前游戏的玩家配置 → 当前商户的游戏配置 → 商户配置 → 已有平台配置 → 默认 96%。删除游戏覆盖后立即恢复继承，已开始的整局不变。

游戏目录分别返回 `configured_target_rtp`（配置目标）、`rtp_source`（来源）、`target_rtp`（已生效模型目标）和 `rtp_status`。未标定时配置目标可以为 96%，但生效目标为 null，状态为 `not_calibrated`。预派彩模式下 `target_rtp` 为 null，继续使用商户的预派彩决策，不能同时把固定 RTP 标成已生效。

2026-11-06 更新：预派彩由商户 URL 是否配置自动决定，移除开关与模式切换确认。地址留空直接走 RTP；填写地址后新付费整局尝试一次回调，3 秒超时、网络失败、非 200、非零业务码（含 3202）、坏 JSON、超限响应或倍数区间校验失败均记录 fallback 并走原 RTP 继承路径。失败记录及整局绑定持久化，操作重试、免费续局和恢复不重复调用；有效决策的计划及已有 RTP 回合继续原绑定。地址不变时旧 enabled/mode 值不再阻止调用。RTP 配置可以独立修改作为回退目标，不清空预派彩地址。未标定游戏沿用原引擎概率并如实显示 not_calibrated。有效决策的合法整局规划失败、状态冲突和钱包错误不被吞掉。商户版本校验及资料事务回滚保持不变。

## 模型与结算

美洲野牛继续使用已有符号权重模型，保留普通与购买免费分别验证、整局绑定及版本恢复。现有资料包含 90% 和 96% 两个已验证目标。

其余游戏新增 `complete-round-mixture-v1` 固定概率模型：原本地引擎生成 2、4、8 或 16 个完整合法回合，按每款游戏、每种付费玩法独立标定的固定概率，选择其中最低或最高派彩回合。模型不读取账户余额、累计投注、历史派彩或短期实际 RTP，不使用累计盈亏反馈。保留引擎中奖金额、免费、续列、购买与收奖状态机；选择结果后冻结根种子，实际每一步仍由同一引擎重放并走原钱包幂等结算。

这是一套新增的本地概率分布，不是原厂概率模型，也不是美洲野牛现有符号权重标定的直接复用。它可能改变奖项分布和波动性；未经比较不能声称保留原始波动率。没有模型时保留原有功能和概率，不隐藏购买或其他入口。

## 验证口径

- 各游戏的普通、购买免费、ante、extra、ultra 等已实现付费模式独立标定，缺少任一已列玩法的报告不能导入模型。
- 训练与验证采用不同种子。验证样本规模由训练估计事先确定，每个模式至少 20,000、最多 2,000,000 个完整付费回合。
- 对固定选择概率使用条件期望 Monte Carlo 估计目标，实际随机选择的回合仍推进连续状态。采用 100 个完整回合为一批的 batch means 计算 99% 正态近似区间；报告同时保留随机重放的实际样本 RTP，不能混淆两种估计。
- 区间必须覆盖目标，半宽不超过 1.5 个百分点，未结束回合数必须为零。最多四次参数修正，每次使用新的独立验证种子；全部失败则不发布。此为统计验证，不是理论精确 RTP 证明或第三方认证。
- 每份报告记录玩法、验证投注参数、引擎版本、规则版本、模型哈希、训练统计、独立验证和失败尝试。报告只证明已验证配置与样本范围，不把现有抓取缺口或其他金额组合推断为原厂已确认规则。

## 执行与状态

后台“模型与标定”可以按游戏创建目标任务。Node RTP worker 执行；美洲野牛保留手动发布，其他游戏在完整校验通过后发布。游戏单独配置也可以恢复为“跟随商户”。不同游戏的模型不会交叉装载；只继承目标值。

商户、游戏或玩家目标变更后，对缺少模型的授权游戏自动排队；已有进行中任务去重。商户 RTP 主页面按全部游戏汇总，先统一为 10000 金额精度；统计明细可以按单款游戏筛选，使用该游戏原生精度。只有已确认结算且已结束的整局进入实际 RTP。

本轮 96% 批量标定使用独立进程，读取公开规则配置，不访问用户钱包或修改用户历史：

```powershell
npm --prefix node run build
node server/tools/calibrate-games.mjs --target-bp 9600 --parallel 3 --output diagnostics/rtp-calibration/9600-v2
```

批量进度写入输出目录的 `progress.json`，通过的完整模型写入 `game-<ID>.json`。批量输出需经同一导入校验后才发布；文件存在不等于已上线。持久化分发使用 `server/config/rtp-round-models.json`，与 Node 应用一起构建，游戏 S3 素材不变。

当前缺口：其余 18 款仍需等待实际标定结果；不能把已实现的任务框架、继承规则或已开始的模拟当成全部游戏已达到 96%。逐款通过、失败原因和发布状态以真实报告及后台模型记录为准。

本地现有演示商户已经手动设置 90%，该显式配置保留，不被默认 96% 覆盖。90% 和 96% 是独立模型目标，不能相互冒用。离线任务的进度和结果通过 `server/tools/import-calibration.mjs` 同步到后台；批次实际启动某款游戏后才领取对应排队任务，不抢占常驻 worker 正在运行的任务。只有通过导入校验的模型才发布；其他任务由常驻 RTP worker 执行。若离线进度停止更新，导入器停止续约，由常驻 worker 在租约过期后重新接管。

本轮最终应用包只包含已实现的执行框架和既有美洲野牛模型，尚未包含其余 18 款的最终标定报告。后台通过的模型保存在实例数据库；迁移到新环境时需要校验并导出模型，或在目标环境重新标定，不能把本地数据库的进度视为新部署已具备相同模型。

2026-11-06 决策与账务关联：v1.11 新整局的 decision_id、game_id、round_id 在首次预派彩前生成并固定，回退 RTP 保留同一标识。钱包候选保存关联信息，重试保持原请求；历史已准备操作不改变回调格式。签名 rounds/get 返回 preparing/active/settling/completed/cancelled、原区间、完整取档 resolution、RTP 回退原因和已确认的钱包精度累计金额；cancelled 仅表示无入账且扣款前明确拒绝，不把钱包不确定或未完免费回合视为取消。round_end 是游戏末步提示，不能代替钱包已确认的 terminal。rounds/changes 与源数据同事务落库，商户处理完本批再保存游标，零派彩末步也会产生变化。当前没有付费后主动撤销/退款新入口，外部手工退款不自动改变整局状态。
