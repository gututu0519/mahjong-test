二、棋盘和符号

基础棋盘是 3 列，每列 4 个逻辑格位。rl 按列排列：
  第一列：rl[0:4]；第二列：rl[4:8]；第三列：rl[8:12]。
扩展时保留原棋盘，并在末尾追加 4 个格位，相当于增加一列。
本批数据最多观测到 8 列；这不是已证明的最大列数。

符号 0：百搭，参与普通符号的中奖匹配。
符号 1：免费旋转符号；sc 等于整张 rl 中符号 1 的个数。
符号 2：在当前样本的结算中不计奖、不作百搭。
符号 3—12：普通赔付符号。图片与每个 ID 的逐一映射尚未整理。
0、1 的用途与原版前端呈现以及响应匹配关系相符；2 的精确美术名称不作推断。

三、中奖判定与计数

对每个普通符号分别计算：
1. 从最左列开始，逐列查找该符号或百搭 0。
2. 遇到完全没有该符号和百搭的列，停止该符号的连续匹配。
3. 至少连续覆盖最左侧 3 列才中奖。后续连续列继续加入获奖位置。
4. 多个符号可以分别中奖，百搭可以同时参与多个符号的计算。
5. 不是把每列符号个数相乘算 ways；本游戏样本采用有效符号个数相加。

wp：按普通符号 ID 列出的获奖位置；上述算法重算全部响应，完全一致。
scs：每个中奖符号的有效数量，不一定等于 wp 数组长度。
es：扩展符号在逻辑棋盘中占据的格位。
bsc：该扩展符号实际代表的数量。
一个获奖扩展块如果占据 k 个格位、实际数量为 n，计数应增加 n-k。

例如抓取行 1548，符号 3 的 wp 有 13 个位置；其中一个扩展块占 4 格，
实际代表 8 个符号，因此有效数是 13-4+8=17，恰好对应 scs["3"]=17。
所有 403 条响应的加权符号计数均吻合。

四、赔付表与结算公式

从实际 sw 记录得到的每单位符号赔付值：
  ID 3        ：5
  ID 4        ：4
  ID 5、6     ：3
  ID 7、8、9  ：2
  ID 10、11、12：1

单个符号基础奖 = cs × ml × 该符号赔付值 × 有效符号数量
总基础奖       = 各中奖符号基础奖之和
最终派奖       = 总基础奖 × 当前 gm

只在本次扩展链结束时发放最终派奖。扩展继续时 tw=0，钱包不提前加奖。
结束时 twbm 对应基础奖；sw 给出各符号的赔付值和基础奖。

实例：抓取行 1545—1548。
  初始有效数量 12，随后扩展到 14、17，最后新增一列未续中而结束。
  最终有效数量 17，符号 3 赔付值 5，cs=0.3，ml=2，gm=4。
  基础奖 = 0.3 × 2 × 5 × 17 = 51。
  最终派奖 = 51 × 4 = 204。
  最初付费 6，该完整回合净增加 198。

注意：ctw 是过程字段，不能当作直接入账金额。
免费旋转样本甚至存在 ctw 为负数而 tb=0、tw=0、余额不变的情况，
例如抓取行 1645 的 ctw=-7.2。直接用 ctw 更新钱包会算错。
钱包和回合派奖应以 tb、tw、bl 等经过核对的字段为准。

五、扩展列与倍率

满足以下任一条件，就继续追加一列：
  A. 当前最右列参与了至少一种仍然连续的中奖符号组合；
  B. 当前最右列出现免费旋转符号 1。

初始 3 列和所有后续扩展列都符合该判断，结果与 ix 一致。
如果某符号曾连续中奖、但后来在某列中断，该符号的奖额保留在已匹配位置，
之后远处再次出现该符号不会跨越空缺重新续接；但免费旋转符号可以让扩展继续。
因此，不能只检查新列有没有 rs.sr 所指的符号，也不能只检查曾经是否中奖。

每处理一个新增列，gm 加 1，包括最后那列没有继续中奖、导致扩展结束的情况。
普通付费起转 gm=1；下一个独立付费回合又重置到 1。
所有扩展步骤都不再次扣除投注：tb=0。

六、免费旋转

已明确观察到的触发：抓取行 1608，扩展链结束时累计 4 个免费旋转符号，
进入 12 次免费旋转（fs.s=12、fs.ts=12），状态从 4 转为 21。
该回合的免费旋转在行 1634—1657 完整执行，最终免费部分共派奖 351.6。

免费旋转特征：
1. 每次免费起转不扣钱；fs.s 减 1。
2. 免费旋转中的扩展步骤不额外消耗免费次数。
3. 免费功能开始时 gm 从 1 开始，不继承触发它的付费扩展链倍率。
4. 进入免费功能后，gm 在各次免费旋转之间保留；增加新列仍使 gm 加 1。
   此次样本最终达到 gm=10；10 并不是已证明的倍率上限。
5. 免费起转时，es 指定的扩展符号全部变为百搭 0；对应计数仍使用 bsc。
   12 次免费起转中 8 次含这类扩展符号，全部符合该转换。
6. fs.aw / aw 在该免费功能内累计已结算的奖额；不能把累计值反复入账。
7. fs.s=0 时，如果还有未完成扩展，则仍会完成扩展后再回到普通模式。

尚不能确认：
  - 3 个免费旋转符号在结束时究竟奖励多少次；当前看到的 3 个发生在继续扩展中。
  - 5 个及更多符号的奖励表。
  - 免费旋转重触发条件、增加次数、倍率和列数上限。
不能仅凭“4 个给 12 次”就宣称“3 个给 10 次、之后每个加 2”。

七、协议状态与钱包约束

观察到的状态：
  1  = 普通付费起转。
  4  = 普通模式的新增列步骤。
  21 = 免费起转。
  22 = 免费模式的新增列步骤。

典型流程：
  普通未触发扩展：1 -> 1。
  普通扩展：1 -> 4 -> ... -> 1。
  触发免费：1 -> 4 -> ... -> 21。
  免费扩展：21 -> 22 -> ... -> 21。
  免费结束：最后一轮扩展完成，22 -> 1。

sid 标识每步响应，psid 关联同一个付费回合及其衍生免费功能。
本次按 psid 分组的 274 个回合全部闭合，没有缺失的中间余额变化。

下列关系在全部响应成立：
  tbb = cs × ml × 10（当前仅验证 cs=0.3、ml=2，且 GameInfo.mxl=10）
  st=1 时 tb=tbb，其余步骤 tb=0
  blab = blb - tb
  bl   = blab + tw
  np   = tw - tb
  下一响应的 blb = 上一响应的 bl
