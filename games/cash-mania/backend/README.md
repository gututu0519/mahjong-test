# Cash Mania 本地普通旋转后端

当前版本接入原客户端的普通旋转，原厂游戏编号为 `1682240`，本地 code 为 `cash-mania`。结算使用项目现有 `GameService`，钱包、请求幂等、流水和最后盘面均由现有事务存储维护。

## 已确认的普通玩法

- 盘面为三列三行，按列排列；支付线只有 `[1,4,7]`。
- 下注金额为 `coin_minor × level × 10`。
- 左右列符号 `0..5` 的金额因子依次为 `[0,1,5,10,50,100]`，金额乘以币值与下注等级。
- 中列符号 `0..11` 的倍数依次为 `[0,1,2,3,5,10,15,20,30,40,50,100]`。
- 中线左右符号相同且不为零时，奖励为左侧金额乘以中间倍数。其余情况奖励为零。
- 原客户端与抓取 GameInfo 的币值为 `[0.02,0.2,2]`，下注等级为 `1..10`。
- 二进制协议使用 digit-sum salt `23`。响应使用对应请求的传输 seed；seed 不进入业务幂等键。

`fixtures/normal_spins.ts` 保存 130 条去除会话、局号和余额的普通局测试证据。它仅供测试读取，生成引擎不引用此文件。原普通局上下格出现的中列符号 `12/13` 已观察到显示值为 `1`，仅对证据计算器兼容；本地生成器不会生成它们。

## 本地概率与功能边界

抓取记录不能证明原厂轮轴带、符号权重或完整概率模型。配置中的左右列权重 `[10,10,30,30,15,5]` 和中列权重 `[0,42,26,15,8,4,2,1,1,1,0,0]` 是明确标识的本地独立抽取模型。每个位置按其所在列的权重生成。所有随机值由结算传入的 seed 和 SHA-256 拒绝采样产生，相同输入可得到相同结果。

按当前本地权重计算，普通旋转模型的理论返还率为 `92.7165%`，计算式为：

`Σ(左右同符号概率 × 左右金额因子) × E(中列倍数) ÷ 10`

此数值只属于当前本地模型，不能解释为原厂 RTP。配置包含 `original_probability_verified: false`，`GameRule/Get` 返回的也是本地模型数值。

免费旋转、重转、轮轴挪动、购买功能和额外下注均未实现。配置列出这些未支持项目；生成器不会触发它们，传入购买或加注请求会在结算前返回错误。原厂 `gwt` 字段与阈值的完整对应关系尚未确认，本地响应固定采用基础中奖动画，不宣称完整复现大赢动画分类。

## 服务与验证

独立试玩端口为 `8103`，由项目启动器创建。计算服务端口由共享服务清单配置，当前接入分配为 `8230`。本模块不负责启停其他服务。

`other/tests/cash-mania.test.ts` 覆盖抓取公式对照、确定性生成、合法下注与非法功能、商户钱包模式、重复 Spin、传输 seed 变化、单笔流水、重开后的 GameInfo 与会话恢复，以及独立计算服务的鉴权和确定性结果。数据库测试只使用临时 SQLite，或显式 `testMode` 的隔离 PostgreSQL 配置。

规则标识使用实际配置的规范 JSON：`sha256(core.encode(config)).slice(0,16)`。项目构建器读取引擎生成 descriptor，不维护手工填写的规则 hash。
