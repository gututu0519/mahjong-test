# Response Capture

> 目录已重组。当前启动命令与路径见[四目录说明](../../docs/project-layout.md)；本文中的旧命令保留为历史记录。

独立本地网页工具：输入网址，打开抓取浏览器，记录实际发生的网络请求及响应。

## 启动

Windows 双击 `start.bat`。需要 Python 3.10 或更高版本；首次运行会安装依赖。
优先使用已安装的 Edge / Chrome，否则安装 Playwright Chromium。
网页地址：http://127.0.0.1:8090

已安装依赖时，可直接运行：

```powershell
.\.venv\Scripts\python.exe app.py
```

## 使用

1. 输入完整的 HTTP / HTTPS 网址，点击“开始抓取”。
2. 在新打开的独立浏览器中登录、点击、滚动或打开新标签页。
3. 在工具网页中搜索请求、选择请求，查看响应体、响应头和请求信息。
4. 点击“停止并保存”，等待“已保存”，再下载 ZIP。

“清空记录”重置当前抓取的请求列表和三个统计计数，后续请求继续显示，不会关闭抓取浏览器。
已保存的响应、HAR 和 ZIP 内容保持完整；“显示全部”可恢复先前记录。清空位置按抓取任务保存在当前浏览器中，刷新页面后仍生效。搜索和类型筛选不会限制清空范围；WebSocket 显示的是整个任务的总数。

同一时间运行一个抓取任务。关闭抓取浏览器也会结束任务。每次使用独立临时浏览器会话；登录状态不会沿用个人浏览器。抓取工具只监听本机 127.0.0.1。

## 抓取页面的游戏采集检查

统计卡下方的“游戏采集检查”直接读取当前选中的抓取会话，每 5 秒更新一次。它检查原站已保存的资源与玩法样本，不读取本地游戏的实现完成状态来判定采集进度。

- 绿色：明确登记的采集范围、所需资源与玩法证据全部满足，可以停止并保存；正常保存后显示采集完成。
- 黄色：仍在采集，或者资源全集、语言范围、功能规则等尚无法确认。等待一段时间没有新增请求不会自动变绿。
- 红色：已确认的资源、依赖或协议数据缺失，或保存失败；展开详情查看具体项目与补抓建议。

“已观察资源保存齐”仅表示已经发生的资源请求得到保存，不能证明尚未触发的动态包、其他语言或特殊玩法已经齐全。清单中的确定依赖、用途未确定的依赖和玩法候选分别展示；没有可靠采集标准的游戏保持无法确认，不给虚假的百分之百。网络失败或检查结果过期时撤销完成信号。

新抓取进程提供 `/api/sessions/<会话编号>/quality`。正在录制的旧进程无需重启：可以在相同目录运行 `python quality_service.py`，只读兼容接口监听 `127.0.0.1:8091` 并读取原有 `8090` 会话；页面在主接口返回 404 时自动使用它。兼容接口不启动、停止录制，不修改原站或任何游戏后端。

## 特殊玩法检测与维护表

在抓取工具打开的原站浏览器中试玩，例如 `https://sdstest.ink/game`。检测器读取这次会话保存的请求和响应，先识别游戏，再按已登记的协议规则判断功能候选和完整回合链。它不会用本地模拟服务的回包冒充原站证据，也不会把进入游戏、下载图片或普通旋转等同于抓到了特殊功能。

工具启动时会尝试启动维护表监督器，每 10 秒检查已保存数据。Node.js 不可用或监督器启动失败不会中断抓取。此流程的状态保存于 `other/diagnostics/feature-maintenance/status.json`，与抓取页面的采集完整度分开；设置 `CAPTURE_FEATURE_MAINTENANCE=0` 可以仅运行抓取。

“抓到候选”“证据完整”“已接入并验证”是不同状态。只有已正常保存的原站完整证据、当前实现、真实本地界面验收和登记专项测试均通过，才自动将登记的 `❌` 改为 `✅`。Excel/WPS 占用工作簿时保留待更新状态，关闭文件后再检查；每次更新保留备份。检测器不自动编写缺失的游戏功能。当前支持范围与验收要求见[维护表监督流程](../../tooling/feature-maintenance/README.md)。

更新这部分代码时，已有抓取进程不会自动加载新 Python 接口。可以独立运行 `npm run features:watch` 监听当前会话，无需中断录制。维护表的完成标记仍按实现与验收标准更新，不能替代上面的采集完整度信号。

## 输出

`captures/<session-id>/`：

- `manifest.json`：请求清单、完整网址、方法、状态、请求和响应头、文件路径、错误说明。
- `bodies/`：浏览器解码后的响应文件及请求体；同一个网址的多次请求分别保存。
- `network.har`：浏览器网络记录，响应内容嵌入其中，停止时完成保存。
- `websockets.jsonl`：WebSocket 收发帧，二进制使用 Base64。
- `capture.zip`：首次下载时生成。

历史记录保存在本地，重启后可查看。预览最多显示 256 KiB 文本或 4 KiB 二进制内容；这不限制已保存的响应文件大小。完整文件可能很大，抓取和 HAR 导出需要相应的内存及磁盘空间。

## 边界

记录范围是此次抓取浏览器会话里实际触发、且浏览器公开给 Playwright 的请求，不会自动遍历整个网站，也不是系统级网络代理。HTTP 404/500 等响应同样保存。

未完成的长连接/SSE、下载流、跳转响应体、浏览器内部请求或被浏览器限制的响应可能无法获得完整内容；清单明确显示失败、不可用或停止时未完成。WebSocket 帧单独保存，不作为普通 HTTP 响应体。Service Worker 保持启用以兼容网站，浏览器未暴露的底层流量不保证覆盖。

没有内置登录绕过或证书校验绕过。登录凭据、Cookie、请求体与响应原文可能含敏感数据；输出仅保存在本机，分享前应检查。

## 验证

关闭 8090 上的工具服务后运行：

```powershell
.\.venv\Scripts\python.exe test_capture.py
```

使用本地测试网站验证界面抓取流程、JSON、二进制、POST、iframe、跳转、404、网络失败、WebSocket、预览、ZIP/HAR、历史恢复和移动布局。

实现依据：[Playwright BrowserContext 网络事件](https://playwright.dev/python/docs/api/class-browsercontext)。

## Joker’s Fortune WinX 解码记录

新录制在 `/sss-jf2/` 页面载入前安装观察器，监听原版 WASM 命令完成后的结果，不改变旋转请求、Promise 或返回值。保存 `decoded-rounds.jsonl`，包括原始解密字节、下注参数、SpinAck 和 ScatterWin；不额外记录登录令牌或私钥。抓取页面实时显示已保存回合数、Scatter 中奖次数及错误数。

先确认页面显示“Joker 解码已接入”，转一局确认回合数增加，再继续录制。正常旋转、Extra Play 和自动旋转均经过同一命令入口。旧记录没有该字段时显示尚未接入，不能把 HTTP 请求数量当作中奖统计。停止后明文文件与 manifest、HAR 一起进入 ZIP。

此支持针对当前 Joker astarte4 客户端，其他游戏仍按原有方式保存网络数据。旧录制只保存 X25519 公钥和加密回包；会话关闭后没有私钥，不能靠重新登录恢复旧回包。旧数据完整保留。

`python test_decoded.py` 使用本地浏览器夹具验证观察器不改变 Promise/异常、明文落盘与 Scatter 计数。
