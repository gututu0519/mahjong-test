# 从抓取数据复刻原版游戏

本项目后续新接入或继续复刻抓取游戏时，默认由抓取的原客户端运行界面，由本地服务处理会话、回合和结算。执行者交付可打开的玩家入口，以及从实际操作追溯到资源、回包和结算记录的证据。下面以 Cash Mania 说明这次做了什么，再给出可用于其他游戏的验收条件。

## Cash Mania 的实际操作

本窗口开始排查前，项目已经登记了 Cash Mania，并有首批静态资源、普通旋转引擎和部分协议适配。初步接入可在提交 `e19a496` 中查看。以下列出本窗口在这个基础上完成的工作。

| 步骤 | 实际操作 | 可复核的结果 |
| --- | --- | --- |
| 1. 找准游戏与输入 | 用游戏名、原厂编号和游戏 API 匹配两个最新相关批次，读取各自的 `manifest.json`、`network.har` 和 `bodies/`。 | 项目代码为 `cash-mania`，目录 ID 为 20，原厂编号为 `1682240`。两个批次的请求能归到同一款游戏。 |
| 2. 核实抓到了什么 | 配对原始 Spin 请求和成功响应，检查正文，按局号组合去重，分开统计普通结果、中间阶段及缺失响应。 | A 批 298 局，B 批 115 局，共 413 个完整普通付费局。其中 204 局有派彩、22 局有挪轴、28 局有两侧重转。另有 1 条请求缺响应。 |
| 3. 从客户端和回包还原规则 | 对照原游戏脚本的状态机、动画控制器、协议字段及抓取中的金额。核对下注档位、支付行、原始盘面、中间盘面、最终盘面和派彩。使用脱敏样本检查二进制编解码往返。 | 原规则为三轴一条支付行。回包按列保存九格，位置 1、4、7 参与结算。挪轴及两侧重转均可属于一个已付费回合。 |
| 4. 补全本地回合与结算 | 在已有普通旋转实现上补充两种特殊表现及对应回包。复用项目会话、钱包、历史和持久化，保存同局事件。用隔离实例验证种子重算、请求重试、重开和单笔流水。 | 已知规则按抓取实现，生成权重作为本地模型单独标明。中间表现不多扣一次投注，重试可恢复同一结果。 |
| 5. 纠正前端路线 | 早期测试走了自写 `play.html`，还使用过自写展示层验证特殊场景。随后撤掉默认跳转，把这些页面、脚本和自制图片移出可服务目录，恢复抓取的 `/1682240/index.html`。 | 玩家从默认链接进入原版 Cocos 客户端。早期自写页面上的动画测试只保留为历史业务测试记录。后续新游戏直接从原版入口开始。 |
| 6. 恢复资源及其依赖关系 | 按原 URL 路径提供启动器、共享模块、游戏脚本、布局、图集、动画、音频和英文资源。逐项记录来源批次、请求编号、长度、原件及输出 SHA-256。按项目图片规则转为 Adam7 PNG，并检查尺寸、解码像素、透明度和调色板。 | 起初复核 253 项，后续共补入 25 项。最终 278 项有来源，34 份原版 JavaScript 字节一致，122 张图片逐项验证通过。 |
| 7. 接好原客户端与本地服务 | 在原入口加载前加入必要适配，处理本地会话、接口和静态资源地址、图片路径，以及本地可见 WebView 的帧调度。沿用原版按钮、布局、绘制逻辑和功能入口。 | 原客户端发送认证、GameInfo、Spin 和历史请求，本地服务按对应契约答复。 |
| 8. 查出原链接卡住的原因 | 用用户提供的原链接复现，查看真实浏览器的加载顺序和调用栈，和成功抓取做单变量对照。旧适配删去了资源主机参数 `or`，使首个共享模块只得到相对父地址。 | 按当前主机和端口补回资源参数后，12 个共享模块、认证和 GameInfo 加载成功。点 GET STARTED 进入原版盘面。 |
| 9. 修复结算成功、界面却报错的回合 | 把原客户端的 `C1016`、隔离试玩第 43 局和正常回合对齐。找到上下展示格能收到空符号的问题，同时修正新局输出和旧局的恢复展示。 | 原来报错的账户重开后余额仍为 1,999.60。其后连续完成 9 局，每局投注 0.20，其中一局有两侧重转，总派彩 0.20，余额为 1,998.00。 |
| 10. 点开菜单补齐懒加载文件 | 从实际菜单依次进入赔付表、规则、历史列表和单局详情。根据 `C1009` 和失败请求，先从旧抓取找回 18 个文件，再从原静态资源地址补抓详情所需的 7 个文件。 | 原版赔付图、规则正文、历史列表和第 86 局详情均可查看。详情内投注 0.20、净变动 0.00、余额 1,998.00，与该局结算一致。 |
| 11. 留存验收证据 | 保存截图、逐局金额和网络结果，运行前端回归及后端专项测试，把未覆盖的玩法和环境写入游戏文档。 | 8 项前端检查通过。12 项后端测试在 SQLite 和隔离 PostgreSQL 各通过一次。本次交付达到已验证范围的本地原版可玩，未制作部署包或上线。 |

本次尚未完成原版挪轴动画的浏览器实测，也缺少完整免费局、购买整轮和最大赢额终止的交易证据。原厂随机权重与精确 RTP 没有得到验证。资源配置中有 79 个 import 和 51 个 native 声明项仍无落盘文件。离线运行已观察到原启动器创建 4 个 SVG 节点，运行时图片格式要求尚未通过。移动真机和弱网渐进显示也待实测。

以下命令用于保有该次游戏实现、专项测试脚本及原始响应的 Cash Mania 验收工作区。从其仓库根目录运行。第一条准备编译产物，第二条重算完整局数和金额，第三条核对特殊局的中间字段，第四条检查原版入口、接入适配和静态资源。

## 后续每款游戏如何执行

1. **确认目标和起点。** 在工作区定位游戏、最新相关抓取、现有实现和可对照的同类接入。保持原始抓取只读。用游戏身份、资源版本和请求链关联输入，单列空正文、缺响应、重复记录及互不兼容的版本。
2. **先让原版前端运行。** 从真实玩家入口恢复启动文档、脚本和依赖目录，包括字体、图集、音视频、语言、子模块及菜单资源。原版渲染器负责一切游戏画面。禁止自制页面、自绘盘面、生成视觉素材或用截图代替交互。将本地接入代码与原件分开，逐项登记必要的 HTML、样式或资源路径变换及来源。
3. **逐款还原协议与规则。** 对齐原客户端、规则文字和同一回合的完整请求响应，梳理启动、普通局、特殊局、结算、恢复和历史。记录金额单位、关键字段和状态转换。其他游戏的游戏 ID、路径、参数、支付线、奖励和概率不得照搬。早先成功接入的共享组件可以复用。
4. **接入真实本地业务。** 按本仓库的 `games/<游戏代码>/frontend/`、`backend/`、`instance/` 和 `docs/` 落地，按需要登记目录、路由和编译目标。使用隔离会话和测试钱包，按整数最小单位算账。持久化回合、交易和中间状态，验证重复请求和重开。证据不足的分支保留原版入口及原有限制，记录待补抓操作，未支持交易在扣款前结束。
5. **用正常入口逐项验收。** 在真实浏览器绕过旧缓存，从用户会点击的链接开始。点进游戏，连续完成普通回合，覆盖有奖和无奖，各次都回到可继续操作的状态。按原版实际功能打开规则、赔付表、历史及一笔单局详情。对声明支持的特殊玩法走完触发、展示、结算和恢复。测试配置强制触发时标明条件。
6. **根据故障补抓并复测。** 黑屏检查入口参数、资源根地址及首个未加载的依赖。显示错误对照失败局、成功局及原版回包。进入菜单才失败时检查按需模块。先从已有各批次查找有正文的响应，再从实际观察到、允许访问的原资源地址或正常试玩路径补抓。修复后重走原先失败的链接、回合或菜单。
7. **按证据交付。** 将源码、来源索引、适配差异和验收记录留在目标游戏目录，私有原包和会话资料留在受控位置。提供本地入口、可复现的启动和测试命令、实测截图或录像、同一局的钱包与历史，以及尚缺项和具体补抓动作。发布包与部署各自记录实际产物和验证结果，按用户要求执行。[构建与发布约定](build-and-release.md)

## “本地原版可玩”的验收条件

以下检查按目标游戏实际提供的功能执行。对于原版没有投注、钱包或单局历史的游戏，记录依据，用实际操作、结果、进度和重开后的存档核验同一状态。

| 检查对象 | 交付时应能复核的证据 |
| --- | --- |
| 原版画面和入口 | 默认链接可直接进入原游戏。运行的启动器、脚本和可见资源能在来源清单中找到，必要改动可与原件对照。 |
| 启动和交互 | 从冷启动进入盘面，有原页面截图或录像和对应的本地业务请求。普通回合能开始、结束并继续操作，画面、动画和适用的声音按实际测试记录。 |
| 结算与恢复 | 同一局号关联投注、派彩、前后余额、历史和流水。普通局验证“结束余额 = 开始余额 − 投注 + 派彩”。有分步扣款或奖励的游戏按实际账务阶段核对。重复请求和重开可核实唯一结算及已存状态。 |
| 菜单和特殊玩法 | 在原版实际提供的菜单查到正文、图集和单局详情。每个声明已完成的特殊玩法都有原始行为证据、实现和对应的本地界面验证。原版无此功能时注明依据。 |
| 资源与兼容性 | 符合本项目图片与前端兼容规则。分别记录文件检查、真实浏览器、真机和弱网的结果。仅达到部分范围时写明该范围和欠缺的证据。 |

验收记录归入对应游戏的 `docs/`。已有专项验证器或维护表的功能按其原有规则登记。某项只有接口 200、静态截图、已下载文件或模拟回放时，该项继续保留待验证。开发验收与运营开放各按现有规则执行。

## 以后发送什么

在本项目发送 **按原版抓取流程复刻《游戏名》，执行到本地可玩并给我验收证据。** 游戏名称明确且抓取已在工作区时可直接开始。数据放在其他位置时附路径或包含正文的抓取包。继续已有游戏可写“继续复刻”；要交付安装包时在同一句加上“并打包这一个游戏”。换项目或交给其他人时，把项目位置、原始数据位置和下列提示词一起交给执行者。
