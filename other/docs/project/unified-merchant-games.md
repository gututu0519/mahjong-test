## 本机测试

### 跨站 iframe 会话（2026-11-07）

已复现并修正：第三方页面通过 iframe 加载 旧美洲野牛测试主机时，带 `ops` 的首页返回 200，随后不带 Cookie 的 `local-auth-bootstrap.js`、`local-frame-clock.js` 和 shared JSON 请求返回 `SESSION_INVALID / Session expired`。这里的错误并不能证明启动会话实际已过期；原网关把所有素材请求也纳入了会话校验。

游戏主机现在允许 GET/HEAD 加载客户端静态素材文件，由原素材处理器继续检查文件路径；HTML 入口、API、fixtures、配置和诊断资料不属于此范围。静态响应不设置会话 Cookie。业务请求优先使用当前启动链接的 `ops` 或显式 Authorization / X-Local-Game-Session，Cookie 作为兼容回退；转发给游戏适配器时统一使用已验证的令牌，过期或错误令牌仍然拒绝。原客户端启动脚本继续从 `ops` 取得令牌并传给 API，无需依赖第三方 Cookie。

验证：新增无 Cookie 的首页、启动脚本、shared JSON、PG 钱包调用回归，检查旧 Cookie 不覆盖显式令牌、Cookie 兼容、跨源请求拒绝及过期会话拒绝；连同 19 款启动/结算、原协议钱包结算及商户隔离回归共 42 项通过。这次完成本地 HTTP 层验证，用户实际嵌入页面和生产 HTTPS/CDN 的浏览器完整验收仍需补做；本次未发布线上素材或应用。

## 授权与接入流程

1. 平台管理员创建商户，配置默认钱包 origin 或六个独立接口 URL 和游戏授权；钱包金额精度固定 10000。系统自动分配商户号、登录账号与签名密钥。商户管理员可在自己的接入配置中修改回调地址。
2. 商户实现余额、扣款、派彩、退款、单笔查询和列表查询。每项可单独配置完整 URL，留空则回退默认 origin 加 `/wallet/v1/balance`、`debit`、`credit`、`refund`、`transactions/get`、`transactions/list`。全部填写后可不配置 origin；签名使用实际 URL 的 pathname，请求/响应格式不变，预派彩继续使用单独 URL。
3. 商户服务端签名调用 `POST /gtt/v1/games/list`，获取获授权游戏。`wallet_compatible` 表示钱包精度是否足够。
4. 调用 `POST /gtt/v1/games/launch`，传入数字 `game_id`、`player_id` 和语言；启用预派彩时还需 `external_username`。
5. 浏览器直接打开返回的完整 `launch_url`。每款游戏使用自己的 origin 和绑定游戏的短期会话。
6. 原客户端协议经网关转接原 Node 协议适配器。统一网关保存确定性计算、钱包扣款/派彩、整局状态与幂等结果。
7. 商户使用原交易查询/重试接口对账；平台或商户后台查询交易。停用或撤销授权后，后续游戏请求被拒绝，已受理的待结算操作可由有权限的运营人员恢复。

## 金额、状态和部署约定

2026-11-07 起，商户钱包统一固定 `minor_unit=10000`（四位小数），后台不再提供选择，创建 API 拒绝其他精度；省略精度时也固定 10000，不受游戏授权列表影响。本机尚无真实商户，现有两位精度测试记录先备份再按金额等值换算，不直接改精度字段。外部商户钱包同样必须使用 10000 单位，修改 GTT 本地数据不代表外部钱包账户已同步转换。

游戏引擎保留原生金额单位：原生 100 的投注与派彩在对外边界精确乘以 100，原生 10000 的游戏直接使用商户单位；不对钱包实际金额取整。原客户端仍使用其原生协议和显示单位，独立游戏入口不变。商户签名目录、启动余额、交易结果的 `wallet` / `settlement` / `outcome` 金额、整局累计和 `resolution` 金额均使用 10000；相应只读单位字段固定为 10000。商户钱包回调不发送 `minor_unit`，响应无需回传，兼容显式回传只能为 10000。预派彩 `bet_amount` 使用主币种四位小数字符串（例如 `"2.0000"`）。单游戏内部 RTP 报表仍按游戏原生精度聚合；商户全部游戏统计统一为 10000 精度后汇总。

接入契约 v1.13.0 已同步 JSON 源文件、Markdown/HTML 指南及 OpenAPI。234 项 Node 回归通过，包括六个钱包接口省略精度、兼容显式 10000、错误精度拒绝、19 款签名查询/恢复/整局金额换算、精确四位余额和原生数据不变；待决策且 resolution 为空时的单位字段另有回归覆盖。本机 8110 签名目录、20 条历史操作及 8112 三种下载格式、接入中心 JSON 已核对为新版；未发布线上应用或素材。

本机一次性换算已完成：8110 环境的两名测试商户均为 10000，保留 20 条历史操作、商户号、账号、密钥和原生游戏状态，本地模拟钱包余额与账务按 100 倍换算，实际币值不变。换算前三库及配置快照保存在本机忽略目录 `services/gtt-gateway/data/backups/precision-backup-2026-11-07T11-16-57-672Z/`；逐条核对历史操作原生钱包与状态不变、结算金额等值，并检查三库完整性。此为本机测试数据处理，不是已实现的生产自动迁移工具；外部钱包账户不在此次数据库换算范围内。

商户、玩家、游戏共同确定状态与历史。原协议缓存仅存放在独立的 `merchant-protocols/<游戏>.sqlite3` 镜像中，权威账务与游戏状态保存在网关数据库。钱包回调超时后以同一交易号恢复，不重新开奖，也不重复扣款。协议 worker 重启后从权威账务同步镜像。

已有美洲野牛 RTP 功能保留，四位钱包也使用相同模型选择和整局绑定。游戏未单独设置 RTP 时继承商户，未配置时默认 96%，保留已有玩家覆盖。其余游戏逐款执行固定概率模型标定，通过验证才生效；配置目标与生效状态分开显示，详见 [RTP 继承与标定](rtp-inheritance.md)。商户预派彩开关适用于全部游戏，限制以实际付费整局为基数，普通、免费、续列和收奖按各款已有状态机处理。优先匹配原区间，最多搜索 3000 个完整合法候选；未命中时选择已搜索结果中不超过上限的最高派彩，允许低于原下限。不会向上取档或修改引擎派彩；没有合法下档时才返回 `PREBET_RANGE_UNREACHABLE`，不扣款。有限搜索不等于全局数学穷举，实际取档及搜索范围写入决策 resolution。

本机使用 `g1.localhost:8110` 至 `g19.localhost:8110`，保留原客户端根路径 API 和素材地址，Cookie 按主机隔离。支持 localhost 子域的浏览器无需修改 hosts。默认启动器与初始化命令均指向当前 8110 环境，未另外保留隔离环境。

生产需显式配置 `game_origins`（slug 到 HTTPS origin 的映射），代理到统一网关并保留 Host、Origin 和可信代理头；每个游戏使用不同 origin。完整素材保持独立发布，网关最小包只带必要协议/启动资源，需挂载完整资源树或配置经验证的 CDN 路由。旧独立 `services/<游戏>/start.bat`、原端口和数据目录保持可用；它们继续使用独立会话和钱包，不会自动变为商户钱包入口。
