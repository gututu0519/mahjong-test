# Buffalo Win 独立服务

在仓库根目录启动：

```powershell
python -m server.services.buffalo_demo
```

也可以双击本目录 `start.bat`，或者运行 `python -m server.run --service-dir services/buffalo-win`。
服务监听 127.0.0.1:8083；主大厅依旧由 8080 的麻将服务提供。启动两项服务后，访问 <http://localhost:8080/demo/?lang=zh#games>，选择「美洲野牛 → 试玩」。

## 已实现

- 独立会话、2,000 初始虚拟积分、SQLite 持久化钱包与逐笔账本。
- 普通旋转、扩展符号计数、新增列、倍率递增、结束时统一结算。
- 原版购买免费入口、75 倍基础投注购买、购买触发续列、10 次免费及结束恢复；重复请求只扣一次，余额不足或回合未结束时拒绝购买。
- 3 个免费符号奖励 10 次免费旋转，每多 1 个加 2 次；免费内可重触发，最后一次免费也可续奖。扩展符号变百搭，倍率在免费功能内保留。
- 第 1 列不生成百搭；2/3/4 格堆叠分别扩展为 3–4/4–6/5–8 个符号；新增卷轴同样支持堆叠及原版表现字段，无本地 8 列截断。
- 原版 v2 JSON 协议适配：登录、GameInfo、Spin、钱包；刷新后可继续未完成的回合。
- 重复请求幂等、并发重复请求只结算一次、过期状态拒绝、余额不足回滚、回合内锁定投注。
- 大厅从后端取得游戏链接，再在 iframe 内运行。

中英文启动、主游戏及原版购买入口均可用。英文启动页、主游戏和赔付表资源来自会话 `8a704656ec204d4899533712d6a8d7b1`，英文规则和免费图集已导入；2026-10-25 本地浏览器已验收英文购买确认、扣款、10 次免费自动旋转、倍率累计及结束返回普通盘面，中文购买弹窗也已验收。进度见 `clients/buffalo-win/fixtures/english-capture-status.json`。可运行 `python -m tools.pg_capture.buffalo_win.import_capture <会话ID>` 增量导入已有支持来源的静态资源，脚本保留既有资源并在版本冲突时停止。原版赔付表、规则面板及 GameRule 接口已从抓取会话 `09637ea7151b461fbc04eee29b8678d5` 恢复；19 个静态资源的来源、响应行号与 SHA-256 见 `clients/buffalo-win/fixtures/restored-original-help-assets.json`。保留原版 UI、图片和文字，没有自制帮助面板。历史面板尚未接入；服务端 JSON 历史接口可用。

引擎 1.1.0 已按抓取的原版中英文说明对齐上述规则。来源为 `clients/buffalo-win/89240957a6.15d79.json`、`clients/buffalo-win/cbff7a4b9e.67a15.json`，客户端继续使用原版面板。GameRule 中的 96.75% 是捕获的原版元数据，不是本地引擎的理论 RTP；客户端保持不显示 RTP 的配置。

## 规则与本地参数

确定性结算参见 `docs/buffalo-win-rules-analysis.txt`。引擎的中奖位置、加权符号数、续列判断和派奖与 789 条离线响应一致（中文 403 条、英文 386 条）。英文脱敏用例 `rule-cases-en.json` 来自会话 `8a704656ec204d4899533712d6a8d7b1`，保留响应行号以追溯。运行服务不会读取这些旋转样本，每一步都由新随机种子生成结果。

本服务配置：`config/buffalo-win.json`。随机权重、堆叠概率、扩展块概率和合法范围内的大小分布仍为本地演示设定，不能代表原厂概率或理论 RTP。只要最右列继续中奖或含免费符号就新增卷轴；每次请求只推进一步，不强制插入中性列。

免费奖励在当前旋转的续列全部结束后统一判断，公式为 `10 + 2 × (免费符号数 - 3)`，不足 3 个不奖励。重触发追加剩余次数和总次数，保留倍率与累计奖金，不重复扣款；新一步清零当步新增次数字段。重触发使用原版说明中的同一奖励公式，但当前捕获没有完整重触发响应，其协议计数通过本地状态、适配器及持久化测试验证。配置校验锁定规则常量；改变规则需要更新实现及版本。新回合自动使用新 ruleset_id，已有未完成回合仍拒绝跨规则版本继续；升级时不清空钱包和历史。

所有金额使用整数分，积分无现金价值。引擎不含充值、提现或支付功能。

## 购买免费旋转（引擎 1.2.0）

2026-10-25 按用户最新抓取 `1979cf39544d4c4c8b86d6e3ac0e036f` 接入购买。该任务仍在录制时通过抓取工具读取最新请求和已落盘响应，没有仅检查旧 manifest。GameInfo 行 523 返回 `fb={"t":0.5,"bms":null,"is":true,"bm":75}`，`gcs.bf={"t":40.0,"bms":null,"is":true,"bm":75}`；原登录配置 `uiogc.bf=1`。本地返回上述两份购买配置并开启对应客户端配置，让原版 `FeatureBuyController` 显示按钮和确认弹窗；没有添加自制购买界面或说明浮层。`t` 的服务器限制语义尚未验证，原样传给客户端，不自行推断限制。

购买请求行 841：`cs=0.02, ml=1, fb=2`，基础投注 0.20，购买成本 `0.20 × 75 = 15.00`。响应 `tb=tbb=15.00, st=1, nst=4, sc=2`；行 850 续列出现第三个免费符号；行 852 续列结束进入 `nst=21, fs.s=fs.ts=10`。之后免费起转和续列均不重复扣款，倍率在免费内延续。行 1034 最后一次免费结束，`fs.s=0, nst=1, fs.aw=16.96`；随后行 1062 的普通起转恢复扣款 0.20。完整购买回合共 25 条响应，累计仅扣 15.00，派奖 16.96。

购买动作只允许在普通回合就绪时发起；触发续列和免费中仍锁定投注，并拒绝再次购买。购买、钱包、状态和账本在同一 SQLite 事务中提交；重试、并发重试及重启后的重试都返回持久化结果，余额不足不推进局面。通用 API 使用 `bet.buy_free=true`；原客户端仍发送 `fb=2`，本地请求继续使用自己的 `btt=2` 会话，不复用原版账号或凭据。新配置并集保留旧档位 `[0.03,0.10,0.30,0.90]`，增加最新抓取的 `[0.02,0.20,2.00]`，这是本地兼容多个原版币种配置的选择。已知 1.1.0 配置的自然回合可继续完成；其他未知规则版本仍受版本保护。

本地购买触发盘面由随机种子生成，采用“两符号起转、首个续列补第三符号”的本地分布，保证本次已验证的 10 次免费；不播放抓取结果。具体符号分布、堆叠与中奖概率不是原厂 RNG。免费中的普通重触发规则保留；购买是否可能初次授予超过 10 次，目前只有一轮样本，尚不能确认。

脱敏证据为 `clients/buffalo-win/fixtures/feature-buy-capture.json`，保留行号、响应 SHA-256、游戏字段和钱包变化，不保存令牌、账号或原始余额。运行 `python -m tools.pg_capture.buffalo_win.import_feature_buy <会话ID>` 可重建此证据及导入当前客户端版本引用的缺失资源。已从同一抓取导入 7 个购买资源；中文购买图集包 `06db6786c.5bb7b.json` 及贴图 `be90a46b-95ec-49d5-a3ff-966cdc067b45.fba48.png` 另外按现有资源配置的路径、版本从该抓取使用的公开 CDN 补齐，共 9 个新增资源。路径、原始来源和 SHA-256 见 `asset-sources.json`；保留既有客户端版本和原文件内容。

专项回归逐步核对这 25 条响应的扣款、派奖、牌面、免费计数、倍率、累计与状态迁移，覆盖重试、并发、余额不足和中途重启。不同平台返回的 `sw[0]` 显示值以及 `rs.pr/sr` 动画提示字段存在差异，其完整含义尚未确认，不宣称逐字节重现；已对照 `sw[1]` 基础奖金和新增列符号、堆叠字段。

本地客户端验收：英文基础投注 6.00、原版弹窗价格 450.00，购买后余额由 2000.00 变为 1550.00；完整完成 10 次免费，本轮生成奖金 187.80，返回普通盘面余额 1737.80。中文原版购买按钮和 450.00 确认弹窗正常。截图保存在忽略目录 `diagnostics/buffalo-rules/feature-buy-zh.png`；后端全项目 187 项测试通过。

仍需补抓：另一次不同投注档位的购买、购买中的刷新恢复、购买起始超过三个免费符号的边界，以及原版不足余额／回合未结束时尝试购买。旧中英文试玩会话返回 `fb:null` 仅说明那些会话未开放购买，不能据此隐藏入口。

## 服务隔离与接口

本目录独立拥有 `service.json`、`config/`、`data/games.sqlite3` 和 `logs/service.log`，不使用麻将服务的数据库或账号。运行数据和日志被 Git 忽略。

- `POST /api/v1/games/buffalo-win/launch`，JSON `{ "language": "zh" }`。
- `POST /api/v1/sessions`；`GET /api/v1/wallet`；`GET /api/v1/history`。
- `GET /api/v1/games/buffalo-win/state`。
- `POST /api/v1/games/buffalo-win/spin`，Bearer token、Idempotency-Key，JSON `{ "previous_sid": "0", "bet": { "coin_minor": 30, "level": 2 } }`。
- 兼容接口：`/game-api/buffalo-win/v2/GameInfo/Get` 和 `/game-api/buffalo-win/v2/Spin`。

客户端的请求仅指向本地服务；原版公开 API 域名描述符只用于旧客户端初始化。认证模板已清理原始用户和令牌。采集原文、分析脚本与 fixtures 均不对 HTTP 开放。

前端资源来自本机捕获会话 ae59ed3f3b5044a0ac6ab404a23a724d，来源及 SHA-256 见 `clients/buffalo-win/fixtures/asset-sources.json`。大厅封面来自 `clients/buffalo-win/2d6aa03a40.9854e.jpg`。

旧命令 `python -m server.services.buffalo_preview` 仅保留为无结算的前端排查工具，与正式服务使用同一端口，不能同时启动。
